Usage Metering & Billing Pipeline

A pipeline that turns raw usage events, such as API calls or gigabytes stored, into monthly invoices and syncs customers and invoices to Salesforce. Raw events are never edited, so every invoice amount can be recomputed from the events that produced it.

  • Ingests 1,000,000 events with 10% duplicates at 38,568 events/s and stores exactly the 900,129 unique ones, via INSERT ... ON CONFLICT DO NOTHING on a client-supplied event ID
  • Replays the full log of 999,589 events twice into an empty database and rebuilds all 200 invoices with identical SHA-256 hashes
  • Pure rating engine (flat, graduated tiers, minimum commit) in Decimal and integer cents, with Hypothesis property tests; late events become next-invoice adjustments priced at the old period's marginal rate
  • Close, Salesforce sync and reconciliation run as jobs on jobq with retries and a DLQ. A live Developer Edition org matched the ledger to the cent: $598,167.89, zero drift
Python, FastAPI, PostgreSQL, jobq, Salesforce Bulk API 2.0, HTMX, Hypothesis, Docker

jobq: Distributed Job Queue

A job queue where a job is never lost and never runs twice by mistake, even when a worker crashes mid-task. Redis dispatches job IDs, PostgreSQL holds the record of every job and attempt, and idempotency keys make the effect happen once.

  • Chaos test: 13 workers killed with kill -9 during a 10,000-job run; 10,000 succeeded, 0 lost, 0 run twice
  • Atomic Lua leasing, heartbeats, a reaper and attempt-number fencing so a stale worker can't overwrite a newer result
  • Exponential backoff with full jitter, a replayable dead-letter queue, cron schedules and 429 backpressure
  • Prometheus and Grafana dashboards, k6 load tests, and 63 tests against real Postgres and Redis
Python, FastAPI, Redis, PostgreSQL, Prometheus, Grafana, k6

Tanks Arena: Real-Time Multiplayer Netcode

A browser tank arena built to study multiplayer networking. The server simulates at a fixed 30 ticks per second and is the only source of truth; clients predict their own tank, interpolate everyone else, and hits are lag-compensated. No game engine, so all the netcode is hand-written and tested.

  • Holds 1,680 players on one Node process within the 33 ms tick budget (p99 26.4 ms)
  • Delta snapshots cut downstream bandwidth per player by 73%, from 24.30 to 6.64 KB/s
  • 0 prediction corrections at 150 ms RTT and 5% packet loss; a cheating client's teleports, input floods and replays are all rejected
  • Reconnect within 30 s keeps the same tank, position and score; 96 tests
TypeScript, Node.js, WebSockets, Canvas, Vitest, Prometheus, Grafana

CytoGuard: Cellular Injury Detection in Cell Painting Screens

An open platform that flags injured wells in Cell Painting drug screens, names the likely injury mechanism, and shows the cells behind every call. Evaluated on 16,701 wells from IDR idr0133, with every compound scored by a model that never saw it.

  • Macro-F1 of 0.462 on never-seen compounds, against 0.146 for the published Pycytominer baseline; AUROC 0.947 for injured vs healthy wells
  • Raw images to injury calls with OME-Zarr, Cellpose-SAM and cp_measure; pixel-level scores match the published profiles at r = 0.95
  • FastAPI job queue, plugin system and a web viewer with segmentation overlays; 20 tests and a one-command Snakemake workflow
Python, Cellpose-SAM, cp_measure, Pycytominer, LightGBM, FastAPI
